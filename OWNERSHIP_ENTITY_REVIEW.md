# Ownership Entity Canonicalization — Manual Review Queue

Generated by the `entity-canon-v1` rule engine from 404 raw investor names across
`neobdm_ownership.db` (ownership_snapshot / ownership_change /
custody_breakdown_snapshot). 404 names → 352 canonical entities; 321 auto-merged
by R0, 6 by R1, 51 by R2, 2 by R3; **24 names (12 pairs) held for review (R4)**.

## Why these are separate

Entity IDs are global — a false-positive merge is expensive and effectively
irreversible once downstream work joins on it. The deterministic rules (R0–R3)
do not strip LTD, LIMITED, PTE, COMPANY, S/A, account designators, or
containment. These suffixes may mark genuinely different legal persons. Each
pair below is flagged because the rules refused to confirm sameness, and the
default for uncertainty is **separate global IDs + review flag**.

## Resolution semantics

Each pair has a `resolution` field. Options:

| Status | Meaning |
|---|---|
| `unresolved` | No human has reviewed this pair yet. Default. |
| `same_entity` | Confirmed: these are two spellings of one legal person. Both names will be reassigned to the same canonical entity. Requires **external evidence** (annual report, KSEI filing, corporate registry). |
| `different_entities` | Confirmed: these are distinct legal persons that merely share a name fragment. Each stays on its own entity ID permanently. |
| `deferred` | Not enough evidence to decide now. Pair stays flagged; will be revisited when historical data accumulates or external evidence surfaces. |

**Do not infer equivalence merely from:**
- The presence or absence of `LTD` / `LIMITED` / `PTE LTD` / `COMPANY`
- S/A (segregated account) designators
- `CUSTODY`, `NOMINEE`, `REGISTRAR` or `FUND` qualifiers
- Jurisdiction suffixes (`SINGAPORE`, `(S) LTD.`)
- One name being a substring of the other
- A name containing another fund or entity name

## Notes on accumulation

As ownership history accumulates, new alias candidate pairs may be flagged by
the `entity_alias_candidate` table. The next scheduled ownership capture will
run `ownership_canonicalize.py` (or its backfill logic) to incorporate new names
into the existing entity groups. Any name in a new R4 pair will automatically
appear in this document on the next refresh.

Resolution of these pairs is not a prerequisite for Experiment #2. The experiment
uses global canonical entity IDs as-is; unresolved pairs contribute two separate
entity IDs, which is the conservative default. Resolving them would reduce noise
in ownership-change features by consolidating what may be the same entity, but
the experiment is designed to run regardless.
